# S3 发票识别基线审计

- 样本：发票归档_待处理目录下 48 份真实 PDF（全部来自 163 邮箱真实同步，pypdf 可开）
- 对象：现有规则解析器 `invoice/parser.py` + `invoice/pdf_text_extractor.py`（pypdf）
- 方法：pypdf 抽文本 → 文档类型分类 → 解析器输出 vs 人工核对的标准答案（价税合计逐份对照大写金额核实）
- 数据：`docs/acceptance/s3_invoice_baseline.json`（逐文件 parser 输出 + 标准答案）

## 一、文档构成：48 ≠ 48 张发票

| 类型 | 数量 | 文件示例 |
|---|---|---|
| 真电子发票（数电票/普票） | 28 | dzfp_*、编号发票、滴滴电子发票、飞猪凭证（含发票号码） |
| 结账单（酒店 folio） | 9 | 结账单20261022*.pdf |
| 行程/报销凭证 | 6 | 天府通行程单、滴滴报销单×3、ETC明细单×2 中 4 份 |
| 租车单 | 2 | rental_agreement_*.pdf |
| 机票行程单（中英） | 2 | 机票出行单.pdf、英文机票出行单.pdf |
| 纯图片 PDF（无文本层） | 1 | 方.pdf（0 字符，只能 OCR） |

**28 张真发票，20 份非发票凭证。** 现有流程不做类型区分，全部按"发票"归档。

## 二、28 张真发票：逐字段准确率

| 字段 | 准确数 | 说明 |
|---|---|---|
| 发票号码 | **28/28** | 全靠兜底正则"文本中首个 20 位数字"碰巧命中——值与标签在 pypdf 输出中分离，非标签命中，属脆弱路径 |
| 开票日期 | **28/28** | 同样靠兜底"首个 20XX年X月X日"命中（恰好每份只有开票日一个该格式日期） |
| 价税合计金额 | **20/28（71.4%）** | 8 张错误，见下 |
| 购买方/销售方 | **0/28 未抽取** | `InvoiceRecord.seller` 字段存在但 parser 从未赋值 |
| 税额 | 未抽取 | 模型无该字段 |
| 发票内容 | 基本为空 | 数电票文本中无"发票内容"标签（是"项目名称"表格），`invoice_content` 恒空 |

### 金额错误根因（2 类，8/28）

**根因 1：`小写` 标记窗先抓到净额（5 张）。**
数电票 pypdf 文本中标签与值分离，值块顺序为 `¥净额 ¥税额` 再 `大写金额 ¥总价`。`_extract_amount_near_markers` 按标记顺序迭代，`（小写）` 窗口先命中 `¥净额 ¥税额` → 取 max = 净额。
- 87.61 vs 99.00、679.25 vs 720.00、302.97 vs 306.00、168.50 vs 169.00、105.09 vs 118.75

**根因 2：空格化标签不匹配 → 回落到全局最大金额（3 张，全部滴滴）。**
滴滴发票文本为 `价 税 合 计 （ 大 写 ） （ 小 写 ） 44.50¥肆拾肆圆伍角整`——字符间有空格，字面量 `价税合计`/`合计` 永不命中，回落 `_find_amount_candidates` 全局最大值 → 抓到行项目单价（62.91/261.07/38.25 vs 真值 44.50/221.70/29.50）。

## 三、20 份非发票：误归档风险（更严重的问题）

现有 parser 对非发票 PDF **不判型直接硬解析**，16/20 被标 `complete`（自动归档门槛）：

| 文件 | 被当成 |
|---|---|
| 滴滴报销单×3 | 手机号 `15982375981` → 发票号码；行程金额 → 发票金额 |
| 天府通行程单 | 批次号 `202610101034302206` → 发票号码；首条行程日 2025-11-13 → 开票日期 |
| ETC 明细单×2 | 租车订单号 → 发票号码 |
| 租车单×2 | 订单号 → 发票号码；`modified_time` 日期 |
| 酒店结账单×9 | 客人账号/随机数 → 发票号码；入住日期 → 开票日期 |
| 机票行程单×2 | 票号 `7514948108` → 发票号码 |

这些"complete"记录进入自动归档会把报销附件当发票做账——**比字段不准更危险**。

## 四、主要失败原因排序

1. **无文档分类**：非发票凭证被判 complete（16/20 误判）。
2. **金额标记策略**：标记顺序迭代 + 小写窗口抓净额（5 张）；空格化标签失配回落全局最大（3 张）。
3. **标签-值分离布局**：数电票 pypdf 输出把标签块与值块分离，号码/日期全靠兜底正则碰巧正确，换一家开具方即可能错。
4. **购销方完全缺失**：`名称：` 后的公司名可稳定定位（值块顺序 购买方→销售方），但未实现。
5. **图片型 PDF**：1 份（方.pdf）无文本层，pypdf 无法处理，需要 OCR。

## 五、S3 后续建议（下一轮做）

1. 文档预分类：`发票号码`/`数电票` 命中 → e_invoice；`行程单|报销单|结账单|租车单` → 凭证类走单独提取路径或标记 `non_invoice`，不进自动归档。
2. 金额：先做"标签间空格归一化"（`价 税 合 计` → `价税合计`），再取 `价税合计` 之后 **max(¥金额)** 或 大写金额相邻 ¥ 值；净额/税额分列 `合计` 双 ¥。
3. 号码/日期：标签与值分离时，值块顺序固定（号码→日期→购买方名→税号→销售方名→税号），按顺序抽取比窗口正则可靠；保留正则作为第二路径。
4. 购销方/税额：从值块顺序或 `名称：`/`税 额` 列提取，写入 `InvoiceRecord.seller` + 新字段。
5. 图片 PDF：标记 `needs_ocr` 单独队列，暂不阻塞。
6. 识别置信度：number/date/amount 三字段命中方式（标签命中 vs 兜底）写入 record，兜底命中的标 `partial` 而非 `complete`。
