# S3.1 发票字段识别优化 — before/after 验收报告

- 日期：2026-10-25；分支 `feature/s3-invoice-fields`
- 样本：`发票归档_待处理/` 中 28 张真实电子发票（S3 基线标准答案集）
- 原则：**每个自动确认字段必须有可核查证据**——`field_sources` 记录证据来源；兜底值可填充但绝不单独使状态变为 `complete`。

## 三、证据来源体系（field_sources）

| 来源 | 含义 | 可否 auto-confirm |
|---|---|---|
| `label` | 标签直接相邻取值（`发票号码：X`、`（小写）¥N`） | 是 |
| `label_window` | 标签存在，值在 120 字窗口内 | 仅号码/日期；金额不行 |
| `daxie` | 大写金额汉字与 `¥N` 小写相邻（两种顺序） | 是 |
| `verified` | 金额另满足 净额+税额=价税合计 交叉验证 | 是（最强） |
| `dzfp_block` | 数电票值区块 `号码+YYYY年M月D日` 结构锚定 | 是 |
| `filename_verified` | 提取值与 dzfp 文件名内嵌值一致 | 是 |
| `fallback` | 全文无约束扫描命中 | **否**（值保留，状态 partial） |
| `filename` / `modified_time` | 文件名/文件时间兜底日期 | 否 |

金额证据分布：`verified` 18、`daxie` 10 —— 无一份靠全局兜底确认。

## 四、金额提取规则（按优先级）

1. `价税合计[:：]N` 或 `（小写）N` 直接标签相邻 → `label`
2. 大写汉字 ↔ `¥N` 相邻（`玖拾玖圆整 ¥99.00`、`44.50¥肆拾…`、`¥310.00叁佰…`）→ `daxie`
3. `价税合计` 窗口内最大 ¥ 值 → `label_window`（不单独确认）
4. 全文最大金额 → `fallback`（不确认，仅供人工参考）
5. `合计 <净>¥ <税>¥` 或任意相邻 `¥净 ¥税` 对与已取金额求和一致 → 升级 `verified`
6. 碎片防护：金额数字仅由空格分隔延续（`¥ 663.7 2`、`¥ 8 6.28`）→ 拒绝，不当作合法值

## 五、非发票防护

- 20 份非发票在新 parser 下 `complete` 数 = **0**（旧 parser 为 16）。
- 兜底字段（订单号当号码、行程日期当开票日期）仍会填充供人工参考，但 `status=partial` + Document Gate 双重拦截，无法进入归档。
