# S3.1a 字段真实性纠偏 — 逐字段质量验收

- 日期：2026-10-25；分支 `feature/s3-invoice-fields`
- 动机：S3.1 初版指标把「字段非空」当「字段正确」——多张滴滴发票的 buyer/seller 被提取为 `统一社会信用代码/`（字段标题被当公司名），但报告仍写 28/28 正确。本轮纠偏。
- 口径：**非空率 ≠ 准确率 ≠ 自动确认率**，三者分别统计。原始真值与逐文件对照仅留本机（`/tmp`），仓库内只提交脱敏指标。

## 一、真实错误回顾

旧 `_extract_parties` 的正则 `名 称[:：] <name> 统一社会信用代码` 中，name 捕获组对空 `名称：` 标签会惰性吞掉紧随其后的标签文本 → `统一社会信用代码/` 被当公司名。修复：

1. 改为**按文档顺序扫描的组织名 + 税号 token**，不再依赖 `名称：` 标签配对（真实票面三种布局：`名称：X 税号`、`公司 税号` 值区块、`公司A 公司B 税号1 税号2`）。
2. 组织名必须含企业后缀（公司/中心/事务所/酒店/…），且通过 `_valid_party_name` 过滤——命中任何字段标题词（名称/信息/信用代码/纳税人/合计/价税…）一律丢弃。
3. 同一 run 内用贪婪匹配取到**最后**一个后缀（`…酒店管理咨询有限公司苏州第一分公司` 不再被截断在「酒店」）。
4. 可识别组织名 < 2 个时 buyer/seller 双双留空 + `review_fields` 标记——不允许凭附近文本猜。

## 三、complete 重定义（字段级审核提示）

`recognition_status=complete` 仍只由核心三字段驱动（号码/日期/价税合计的强证据源）。新增 `record.review_fields`：附加字段缺失或仅有兜底证据时记入（如 `["seller","tax"]`），供预览/台账人工复核——**complete 不再掩盖附加字段问题**。
